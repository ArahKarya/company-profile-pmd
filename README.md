> A product of **Arah Karya Sinergi (AKS)**.

Meridian is the starting point AKS uses for corporate profile sites. **Five pages in two
languages** — Indonesian and English — driven entirely by content, with an **admin panel** so
the client edits their own copy, images and brand colours. Handing a site over no longer means
handing over the codebase.

The locale split is real, not a translation layer: **two root layouts**, each emitting its own
`<html lang>`, with a **per-locale route table** so `/layanan` and `/services` are the same page
under different URLs, and every link, active state and language switch follows automatically.

## ✨ Why Meridian

| Problem | Solution |
|---|---|
| Every new client site starts from scratch | Five ready pages, ten routes, all sections built |
| Rebranding means hunting hardcoded strings across components | All copy in `id.ts` / `en.ts`; all brand facts in `site.ts` |
| Colour changes leak into a dozen stylesheets | One `:root` token block in `theme.css` drives the whole palette |
| i18n bolted on after launch | Two locales are the architecture, not a plugin |
| Third-party artwork licensing risk | Logo, diagrams and decorative art generated by script — no external assets |
| Every copy tweak becomes a developer ticket | `/admin` — the client edits content, contact details, colours and images themselves |

## 🏛️ Architecture

```
    ┌───────────────────────┐        ┌──────────────────────────────┐
    │  app/(admin)/         │ writes │  Postgres                    │
    │  the client edits ────┼───────►│  site · theme · page content │
    │  copy, images, brand  │        │  media · users · sessions    │
    └───────────────────────┘        └──────────────┬───────────────┘
                                                    │ reads
                    ┌──────────────────────────────┐│
                    │  src/content/                ││ fallback when
                    │  ┌────────────────────────┐  ││ DATABASE_URL
      Defaults ───► │  │ site.ts   brand facts  │  ││ is unset —
      and seed      │  │ id.ts     Indonesian   │  ││ also the seed
                    │  │ en.ts     English      │  ││
                    │  │ types.ts  the contract │  ││
                    │  └───────────┬────────────┘  ││
                    └──────────────┼───────────────┘│
                                   │  typed content objects
                    ┌──────────────▼───────────────┐
                    │  src/components/             │
                    │  layout/  sections/  ui/     │  ◄── never edited per-client
                    └──────────────┬───────────────┘
                                   │
              ┌────────────────────┴────────────────────┐
              │                                         │
     ┌────────▼─────────┐                     ┌─────────▼────────┐
     │  app/(id)/       │                     │  app/(en)/       │
     │  root layout     │                     │  root layout     │
     │  <html lang=id>  │                     │  <html lang=en>  │
     └──────────────────┘                     └──────────────────┘

   src/styles/theme.css ──► design tokens; the admin panel overrides them per site
```

**Three root layouts**, not one: Next.js allows a single `<html>` element per layout tree, each
locale needs its own `lang`, and the admin panel wants neither the public theme nor the site's
title template. That is why there is no `src/app/layout.tsx`.

**The content contract is one thing in two places.** `src/content/types.ts` types both the
bundled defaults and the JSON stored per page, so the editor forms and the page components are
built against the same shapes — a field cannot exist in one and not the other.

**No database, no problem.** With `DATABASE_URL` unset the site serves the bundled content and
the panel says what it needs. A fresh clone runs before any database exists.

## <a id="admin"></a>🔐 Admin panel

At `/admin`, behind a login.

| Section | What it edits |
|---|---|
| **Content → *page*** | Every section of that page, per language — headlines, paragraphs, images, feature lists, service categories, hover diagrams |
| **Site & contact** | Name, logos, favicon, email, phones, address, map, and the URL each page lives at |
| **Brand colours** | The palette and layout constants, with a live preview |
| **Media library** | Upload, describe and delete images |
| **Users** | Accounts and roles — administrators only |

**Roles.** An *administrator* does everything; an *editor* changes content and settings but not
accounts.

**Publishing.** No draft state — saving publishes. Each save revalidates the public tree, so the
change is live on the next request.

**Passwords** are scrypt digests from `node:crypto` — no native hashing dependency, so the
template installs cleanly everywhere. Changing a password signs that account out of every
session.

**Uploads** are stored as bytes in Postgres and served from `/api/media/<id>` behind an
immutable cache header. That keeps the site portable across hosts, including read-only
filesystems, at the cost of some database size. Files shipped in `public/` are not listed in the
library but can still be referenced by path.

**Where the guard lives.** In the dashboard layout, not middleware — Edge middleware cannot
reach Postgres. Every server action re-checks the session independently, because a layout guard
protects the view, not the mutation.

## 🔁 Rebranding pipeline

The panel covers all of this. Editing it as code changes the *defaults* a fresh install starts
from — which is what the seed loads.

**1. `src/content/site.ts`** — name, logo, favicon, routes, email, phones, address, map URL,
copyright. This is also where the per-locale route table lives, so renaming `/layanan` to
`/services` is a one-line change.

**2. `src/content/id.ts` and `src/content/en.ts`** — all copy, plus which image each section
uses. The two files mirror each other section for section. `**bold**` inside a headline line
renders as `<b>`.

**3. `src/styles/theme.css`** — the `:root` block holds the whole palette, the typography stack
and the layout constants:

```css
--brand-dark: #0f2d3d;        /* dark sections, solid navbar */
--brand-darker: #071a24;      /* footer */
--brand-accent: #2f9e8f;      /* pills, active states */
--brand-accent-soft: #6cc2a8; /* headings, markers */
--brand-accent-deep: #1c6b60; /* accent on light backgrounds */
```

**4. `public/`** — replace `images/` with your own photography and `brand/` with your own logo
and diagrams.

To add a typeface, wire it up with `next/font` in the two root layouts and point `--font-body` /
`--font-display` at the resulting CSS variables.

## 🖱️ Hover diagrams

`HotspotFigure` swaps the image while a region is hovered or focused. Regions are expressed as
**percentages of the image box**, so they track the image at any size without a resize listener,
and each one is a real `<button>` — the diagram is keyboard-reachable.

```ts
diagram: {
  base: { src: "/brand/process-plant.svg", alt: "Plant operations" },
  hotspots: [
    { id: "intake", label: "Intake", rect: [4.1, 39.1, 18.5, 41.3],
      preview: "/brand/process-plant-1.svg" },
  ],
}
```

`rect` is `[left, top, width, height]`, all 0–100.

## 📁 Repo structure

```
prisma/
  schema.prisma    Data model
  seed.ts          Loads src/content/ into the database
src/
  app/
    (id)/          Indonesian routes — own root layout, lang="id"
    (en)/          English routes    — own root layout, lang="en"
    (admin)/       Admin panel       — own root layout, no public theme
      admin/login/         unguarded
      admin/(dashboard)/   guarded shell and every editor
    api/media/[id]/        serves uploaded images
    globals.css    Bootstrap + icons + theme, in cascade order
  components/
    layout/        Navbar, Footer, PageShell
    sections/      One component per page section (9 sections)
    ui/            Lightbox, HotspotFigure, ArrowLink, RichText
  content/
    types.ts       The contracts every content file satisfies
    site.ts        Locale-independent brand and contact facts
    theme.ts       Default colour tokens
    id.ts, en.ts   Copy
  server/
    db.ts          Prisma client; null when DATABASE_URL is unset
    auth.ts        Sessions and guards
    password.ts    scrypt hashing
    content.ts     Reads content, falling back to src/content/
    actions.ts     Every mutation the panel performs
  styles/
    theme.css      Public design tokens and site rules
    admin.css      Admin panel styles
public/
  images/          Demo photography (Unsplash, Free licence)
  brand/           Generated logo, process diagrams, decorative art
scripts/
  fetch-demo-photos.mjs      Re-downloads the demo photos
  generate-brand-assets.mjs  Regenerates the placeholder logo and diagrams
```

## 🚀 Quickstart

```bash
npm install
cp .env.example .env      # set DATABASE_URL
npm run db:migrate:dev    # create the tables
npm run db:seed           # load default content and the first account
npm run dev               # http://localhost:3000
```

Sign in at `/admin`. The seed prints the account it creates — `admin@example.com` /
`changeme123` unless `ADMIN_EMAIL` and `ADMIN_PASSWORD` are set first. **Change that password
immediately.**

```bash
npm run check             # lint + typecheck + production build
```

Node **24+** (`.nvmrc` included) and Postgres **14+**.

<details>
<summary>Running without a database</summary>

Skip the `.env` and database steps. The site serves the bundled content from `src/content/` and
the panel reports that it needs a connection. Useful for a first look, or for a static build
where nothing is edited after deploy.

</details>

### Deploying

```bash
npm ci && npm run build
npm run db:migrate        # then npm run db:seed on the first deploy only
npm start
```

The build output is `standalone`. Public pages are prerendered and revalidated on save, so a
database outage degrades to stale content rather than an error page.

### Adding a page

1. Add the key to `PageKey` and `PAGE_ORDER` in `src/content/types.ts`, and to the `PageKey`
   enum in `prisma/schema.prisma`; run `npm run db:migrate:dev`.
2. Add its route to both locales in `site.ts`, and its nav label, metadata and content to
   `id.ts` / `en.ts`.
3. Create `src/app/(id)/<route>/page.tsx` and `src/app/(en)/en/<route>/page.tsx`, rendering
   `<PageShell locale="…" page="…">` around your sections.
4. Add its editor under `app/(admin)/admin/(dashboard)/content/[locale]/[page]/editors/` and
   register it in `ContentEditor.tsx`.
5. `npm run db:seed` to create its rows.

Navigation, active states and the language switcher pick it up automatically.

## 📷 Demo content

The photography is from [Unsplash](https://unsplash.com) filtered to the Free licence, which
permits commercial use without attribution. It is **placeholder material — replace it before
shipping**. `scripts/fetch-demo-photos.mjs` lists every photo id if you need to trace one back
to its source.

The logo, process diagrams and the decorative band are generated by
`scripts/generate-brand-assets.mjs`, so the template ships no third-party artwork.

The map on the contact page uses Google's keyless `output=embed` form with a placeholder query.
Swap `mapEmbedUrl` in `site.ts` for your own address.
